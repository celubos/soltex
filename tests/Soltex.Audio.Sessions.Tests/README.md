# Session service checks

Default execution runs deterministic checks through an in-memory backend and never opens Windows audio endpoints. It checks identity rejection, invalid scalars, worker serialization/MTA ownership, cancellation and disposal. Run with `dotnet run --project tests/Soltex.Audio.Sessions.Tests --artifacts-path <external-build-directory>`.

Explicit `--live-read-only [snapshot.json]` additionally reads endpoint/session controls and measured peaks, checks that five 100 ms frames reuse COM discovery leases, and optionally saves a snapshot. With `dotnet run`, pass these arguments after `--`. The live mode does not assert that any audio hardware or active application is present, and it never sets volume/mute, creates a stream or changes routes/defaults. Snapshots can contain private executable paths: retain them outside the repository.

The separate opt-in live mode controls only its own unique test executable process. Run the built `Soltex.Audio.Sessions.Tests.exe` apphost directly (with `DOTNET_ROOT` set if needed), passing `--live-own-session --endpoint <physical endpoint ID> --receipt <new receipt.json>`. It rejects a shared `dotnet.exe` host, virtual endpoint names, a muted/very quiet physical output, ambiguous self sessions, and interference at the test frequency. It snapshots the exact own PID/creation time, session gain/mute, defaults and physical endpoint settings. It opens a quiet 1619 Hz tone (source amplitude .002), measures physical loopback at session volume .5 and .25, requires -6.02 ±1 dB, checks mute suppression, and restores the original session gain/mute in finally while the session remains alive. It verifies unchanged defaults and physical endpoint volume/mute. Ctrl+C requests cancellation followed by recovery; do not terminate the process during recovery. Receipts are never overwritten at startup and checkpoints are replaced atomically through sibling temporary files. This mode does not route applications, change endpoint volume, set defaults or control any other process.

Default execution also runs the 15 linked signal/PCM assertions, without opening audio devices. The linked source is Soltex's own transport-test signal detector, not vendor code.

The physical recorder runs in a spawned owned child, with a distinct process-local audio session. Its PID, creation time, executable digest and session identity are checked; every measurement also requires its gain to remain exactly1 and mute=false. This prevents changing the renderer's gain from also attenuating its measurement stream. NAudio 2.3 initializes capture/playback with the default session GUID; combining both in one process yields squared attenuation. The test retains the linear one-stage -6.02dB requirement and does not compensate or normalize recorded samples. The recorder child opens only the explicit endpoint loopback, accepts measure/stop commands over redirected standard streams, and never calls audio setters. It is closed after restoration; only the exact spawned process handle can be terminated if graceful shutdown fails.
