# Independent application routing

`AppRoutingService` implements explicit selected-application routing without GG. It does not create audio endpoints. `PreviewAsync` checks a current session, an active destination and the Windows audio-policy capability; `RouteAsync` is the deliberate apply action. The selected session must have a verified executable path and process birth time, represent a controllable single process, and still exist in a current session snapshot. A retained process handle revalidates PID, start time, path and interactive session immediately before each native operation.

The implementation uses the metadata-verified internal Windows policy ABI described in `tests/Soltex.Audio.Routing.Tests/README.md`. This ABI is OS dependent and may be unavailable. The service surfaces capability errors instead of changing defaults or using another endpoint. Windows ultimately accepts a PID, so identity checks narrow but cannot eliminate the native exit/PID-reuse race. No undocumented setter can make that transaction atomic with process lifetime or another route manager.

Routing updates all three roles for the chosen direction and preserves all six exact prior raw policies, including null versus empty values. A unique local journal is flushed before the first mutation and before every subsequent role. Partial failure/cancellation rolls back only entries still equal to this operation's intended value; newer choices remain intact. Restoration similarly compares before writing. If the process exits, the journal remains available for explicit restoration against a newly selected current session at the same executable path. The service never launches, restarts or terminates the user's application.

`PolicyConfirmed`, `SessionObserved` and `RequiresStreamRestart` are distinct. A successful getter readback does not prove stream migration or sound. Render observation requires active same-process sessions on the chosen endpoint; capture delivery is not claimed by the render session observer. An existing application may need to reopen its own stream.

`RoutingProfileStore` saves versioned rules by normalized executable path and direction. `LoadAsync`, `ImportAsync` and `ExportAsync` never replay rules. Applying a saved rule requires selecting a current application and calling `RouteAsync` explicitly. Rules have bounded count/document size, duplicate rejection and atomic replacement. Successful routing saves intent; undo restores prior intent only when the saved rule still belongs to that operation. `GetHistoryAsync` exposes the last 100 journals for recovery after restarting the UI.

The constructor performs no native activation. All service operations serialize asynchronously, so UI callers can await them without blocking the dispatcher. Disposal drains the current operation and owned MTA services. Policy, journal and profile data stay in the caller-selected per-user preferences directory.

The existing `WindowsAudioPolicy.LaunchOwned` fixture API remains available for controlled live experiments; its child shutdown behavior does not apply to selected user applications. `Soltex.Audio.Routing.Tests --self-test` runs deterministic fake-policy transaction, recovery, identity and profile checks without activating native policy or audio. The selected-application path is implemented and tested with fakes; arbitrary applications, packaged apps and browser subprocesses still need live testing on Windows.
