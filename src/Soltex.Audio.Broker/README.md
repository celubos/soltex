# Soltex privileged audio broker

The broker lets the ordinary Soltex UI use the owned driver's narrow PCM transport without running the UI as administrator. It does not install or start a service/driver, open physical microphones, change Windows audio settings, run programs, or accept arbitrary device paths. This is source and test coverage for a privileged service, not an installed or production-qualified deployment.

## Composition

The library exports `BrokerAudioDevice : IOwnedAudioDevice`. Compose it as `new OwnedAudioTransport(new BrokerAudioDevice())`. It lazily connects to the fixed local pipe `Soltex.Audio.Broker.v1`. A read-only SCM preflight immediately fails if the service is missing, stopped or inaccessible, avoiding a pipe-connect delay during ordinary endpoint enumeration. It does not retry a request after a disconnect, cancellation or unknown write outcome; construct another connection only as a deliberate recovery action.

The CLI project `Soltex.Audio.Broker.Cli` builds `Soltex.Audio.Broker.Service.exe`. Its sole supported argument is `--service`, entered through the Windows Service Control Manager for service `SoltexAudioBroker`, running as LocalSystem in a dedicated process. Launching it as an ordinary console application does not install or elevate anything. Service STOP/SHUTDOWN cancel the server, close the pipe and release the native adapter after any pending operation completes. SCM startup failure is reported as a service failure.

The server opens only `OwnedAudioTransport.OpenNativeDevice()`, which fixes the native path to `\\.\SoltexAudioTransport`. The protocol permits exactly QUERY for buses 0–5, READ for render buses 0–3, and WRITE for microphone/stream capture buses 4–5. Version, lengths, frame count, direction, generation and sequence fields are bounded/validated before opening or forwarding to the driver. PCM generation/producer sequence preconditions remain the driver's atomic responsibility. No service-management, registry, filesystem, process-control, driver-installation or other kernel operations exist in this protocol.

## Identity and lease policy

The server pipe rejects remote clients, uses first-instance ownership and allows one instance. Its DACL grants LocalSystem full access and interactive users read/write access; connecting alone does not grant a driver lease. After reading each request, the server impersonates the pipe caller and checks its authenticated impersonation token, kernel-reported client PID/session, process creation time and primary token SID, active WTS session state, and the logged-on user's WTS token SID. The session must be the nonzero current active console session, and all SID/session observations must agree. The driver buses are global: RDP-only sessions are deliberately refused until per-session driver isolation is qualified. Remote control of the existing console session is unaffected. The process must still be running. Before each driver operation the server revalidates this identity; a PID, birth time, SID or session change closes the lease. LocalSystem's `WTSQueryUserToken` use requires the normal LocalSystem TCB privilege; a missing privilege fails closed.

Before sending audio, the client checks the pipe's kernel-reported server PID against SCM's running dedicated `SoltexAudioBroker` PID, verifies the configured service account is LocalSystem, and reads the server process birth time/session zero. This uses SCM as the service-account authority so ordinary users do not need permission to open a SYSTEM process token. Subsequent operations must retain the same identity. A counterfeit pipe owned by an ordinary process cannot satisfy the service identity check. An administrator who can change trusted service configuration is outside this boundary and already controls privileged execution.

Only one authenticated connection owns the native adapter. A second user/session cannot share that lease. Disconnect, malformed frame, replayed request number, identity failure, idle timeout or I/O failure closes the connection. Requests have monotonically increasing connection-local numbers; writes are never automatically replayed. Frames are capped at 19,272 bytes. Client I/O has a five-second bound; the server idle frame bound is five seconds and native exchange wait is three seconds, in addition to the native adapter's own two-second cancellation bound. A native call that outlives the broker deadline retains its device and exclusive lease until completion; it is never disposed while still running. Cleanup failure retains the lease rather than allowing another adapter owner.

These are managed deadlines, not guarantees against a stalled kernel. The signed driver's native cancellation/completion and resource lifetime must still be validated. The default service runs a single connection; another client may wait for pipe availability only within its own bounded connection deadline.

## Deployment boundary

Building the code installs nothing. A reviewed deployment must verify the signed driver and broker package, place the service executable and every dependency in an administrator/SYSTEM-write-only directory, configure the quoted full executable path plus `--service`, use LocalSystem and `SERVICE_WIN32_OWN_PROCESS`, and protect service configuration from ordinary-user changes. Ordinary users require SCM query-config/query-status permission, not service creation, reconfiguration or elevation. Do not deploy directly from a user-writable checkout. Service startup policy and installation/removal belong to the deployment tooling, not this library.

The current service does not claim production signing, installer acceptance, native impersonation/SCM/WTS integration tests, or installed-driver transport qualification. Its failure messages deliberately say when that prerequisite is unavailable.

## Verification and sources

`tests/Soltex.Audio.Broker.Tests` runs the actual bounded protocol/client/server over local pipes with fake identity/device boundaries. It tests the same pure Windows identity policy used by the native verifier, denied identity and service impersonation, PID birth/SID/session changes, unavailable-service preflight, malformed/replayed/oversized frames, multi-client session isolation, disconnect release and ownership retention across a timed-out native call. No SYSTEM service, driver or real audio endpoint is opened by these tests.

Primary API contracts used: [pipe client PID](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeclientprocessid), [pipe server PID](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-getnamedpipeserverprocessid), [WTSQueryUserToken](https://learn.microsoft.com/en-us/windows/win32/api/wtsapi32/nf-wtsapi32-wtsqueryusertoken), and [SCM process status](https://learn.microsoft.com/en-us/windows/win32/api/winsvc/nf-winsvc-queryservicestatusex).
