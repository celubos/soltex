# Windows session mixer

This library uses Windows Core Audio directly and does not communicate with GG, Sonar or a vendor driver. It opens no audio stream, installs nothing and does not change defaults or application routing. The caller must explicitly invoke volume/mute operations. Endpoint volume remains the existing `AudioDeviceService` responsibility.

`AudioSessionService.GetSnapshotAsync()` returns active playback endpoints and their current sessions, measured peaks, volume and mute state. Missing meters remain null. Session/process disappearance produces an error rather than a synthesized value. A session with inaccessible identity, multiple owner processes, or system sounds is read-only. `Classification` only recognizes known virtual-device names; `Unknown` must never be presented as proof of physical hardware.

`WatchAsync(TimeSpan.FromMilliseconds(150), cancellationToken)` yields sequential frames without accumulating them. One MTA owns a bounded queue and all COM leases. Discovery refreshes at most once per second; intermediate frames read cached meters/controls. Limits are 64 endpoints and 256 sessions, with explicit partial-inventory errors. Failed leases are released and rediscovered on the next discovery interval. Polling discovery has up to one second latency and is not a claim of notification-perfect observation of sessions that exist only briefly.

Use the full `AudioSessionInfo.Key` for `SetSessionVolumeAsync(key, scalar)` and `SetSessionMuteAsync(key, muted)`. Keys must have been observed by this service. Each write obtains a fresh endpoint/session enumerator, revalidates the instance ID, process ID and creation time, rejects system/multi-process/expired sessions, invokes one setter, then confirms readback. `Applied` means the requested value was observed. `WriteIssued` means the setter was called, including a rejected HRESULT or failed readback; never retry blindly after an uncertain result. Windows does not provide an atomic identity-check-and-set transaction. Holding the resolved session object prevents retargeting a setter to a different session, while process creation-time checks narrow PID reuse races.

Cancellation prevents a queued operation from starting. Once started, the operation completes confirmation even if its token is canceled. Dispose asynchronously to drain queued commands and release COM on the owner thread. There is no automatic state restoration on disposal: explicit mixer adjustments are normal user settings.

Interop follows Microsoft's [IAudioSessionControl2](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nn-audiopolicy-iaudiosessioncontrol2), [GetProcessId](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessioncontrol2-getprocessid), and [GetSessionEnumerator](https://learn.microsoft.com/en-us/windows/win32/api/audiopolicy/nf-audiopolicy-iaudiosessionmanager2-getsessionenumerator) contracts. Endpoint declarations are linked from Soltex's existing Core Audio implementation. No third-party library or copied vendor implementation is included.

The shared Core Audio factory activates the native enumerator through `CoCreateInstance` and obtains a [unique interface RCW](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.interopservices.marshal.getuniqueobjectforiunknown). This avoids a shared-MTA COM identity collision between Soltex's endpoint declarations and NAudio's typed COM coclass. Each owner releases its own wrapper. The opt-in read-only regression exercises both activation and disposal orders with the endpoint provider, both services and NAudio alive together.
